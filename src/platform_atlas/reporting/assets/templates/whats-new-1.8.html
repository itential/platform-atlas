Resilience

Resume Interrupted Captures

A Ctrl-C or connection drop no longer means starting over. Atlas checkpoints every collector result atomically so you can pick up exactly where you left off.

  • Checkpoint written after every collector
  • Re-run session run capture to resume from last checkpoint
  • Works in both interactive and --headless mode
  • Checkpoint cleared automatically on successful completion

Governance

Per-Environment Rule Suppression

Suppress rules for a specific environment with a required justification. Suppressed rules always run — they appear in amber so intent is visible, not silent.

  • ruleset skip-rule <NUM> --reason "..."
  • Minimum 10-character reason stored with each entry
  • Amber Suppressed badge in reports and the WebUI ruleset table
  • Justification surfaced inline in the rule detail modal
New Commands

Triage and maintain from the CLI

platform-atlas support-bundle collects a diagnostic ZIP in seconds — Platform health endpoints, redacted Atlas config, and (in Extended mode) SSH-fetched platform, webserver, and MongoDB logs plus system info. Hand it straight to the team without digging through file paths.

platform-atlas ruleset update checks GitHub for a compatible ruleset version, verifies the download with SHA-256, and writes it atomically. The dashboard surfaces a slim notice panel when an update has been checked but not yet applied — it disappears automatically once you run the command.

Both commands accept --yes for non-interactive pipeline use. support-bundle also takes --log-days N and --output PATH.

Kubernetes

11 new rules. Deeper capture.

KBS-001–004 are now enabled and KBS-005–015 are brand new — bringing total Kubernetes coverage to 15 active rules across probe configuration, resource limits, HPA settings, and live pod health. The master ruleset now contains 119 rules total.

The Kubernetes collector picks up eleven additional fields from values.yaml: startup, liveness, and readiness probe timeouts; initial delay seconds; startup failure threshold; and CPU/memory request and limit presence. When kubectl is available, Atlas also captures live pod restart counts, HPA min replicas, node count, and deployment kind.

KBS-013 (restart count) and KBS-014/015 (HPA) require kubectl access and skip cleanly when it is not configured — no false failures.

Platform Support

Atlas runs on Windows 11

Atlas is now fully supported on Windows 11 workstations with no workarounds or separate builds. Standard and Extended modes both work. The offline RHEL/Rocky 8+9 bundle is unchanged.

UTF-8 is configured at startup so em dashes, box-drawing characters, and checkmarks render correctly in Windows Terminal and PowerShell. File locking, permissions, socket paths, and keyring configuration are all platform-aware.

The SSH agent probe queries ssh-add -l directly — no SSH_AUTH_SOCK required. ControlMaster transport raises a clear, actionable error on Windows rather than failing opaquely at connect time.

Architecture discovery warnings 1.8

Atlas now flags cross-datacenter latency (IAP, MongoDB, Redis, and Gateway in different DCs), single-node availability risk (no HA, no replica set, no standby), and cloud cross-region MongoDB — derived automatically from capture data and rendered in both the architecture report and the WebUI /architecture page.

🔌

ControlMaster socket preflight 1.8

When the active topology includes ControlMaster nodes, Atlas verifies every socket file exists before capture starts. Missing sessions are blocked with the exact ssh -M -S ... command to open them. A reminder panel then lists all open sockets at the "ready to start?" prompt.

🔔

Ruleset update dashboard notice 1.8

After ruleset update finds an available version but you haven't applied it yet, a slim info panel appears above the dashboard footer. It disappears automatically once the update is applied, so the nudge never gets stale.

Quality-of-life fixes 1.8

session run all no longer continues to validate and report when capture is declined. config doctor now shows separate rows for OS keyring and Vault when the Vault backend is active. ControlMaster modules correctly display CONTROL_MASTER in the capture progress panel instead of SSH.
