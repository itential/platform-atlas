What's New in 2.2

Setup gets out of your way, upgrades get a guided path, and reports get a redesign. First-run no longer forces an environment, tier upgrade walks you through Extended step by step, and an early RBAC tab lands in the Unified Report. Plus encrypted setup bundles, a redesigned Support Bundle viewer, and an outbound network policy switch.

Headline

The big ones

The features that change how you work day-to-day.

CLI

Setup no longer asks about creating an environment

First-run setup now asks for theme and organization name only — SSL verification defaults to off (flip it later in config edit). There's no more "create your first environment now?" prompt; setup finishes with a summary telling you to run platform-atlas env create when you're ready. Commands that need an environment show a clear message and exit; everything else (config doctor, config edit, guide, the dashboard) proceeds normally with a one-line nudge.

CLI

tier upgrade, guided

Instead of flipping straight to Extended and leaving you to configure everything, tier upgrade is now a staged walkthrough of exactly what Extended needs — deployment topology, SSH, and MongoDB/Redis connections — on your active environment. Fill it in at the terminal or in a browser form (tier upgrade --from-file finishes the browser flow). The tier only switches at the very end, so backing out at any point leaves Standard Mode untouched.

WebUI

RBAC tab Early

An opt-in (enable_rbac_collection: true) look at Platform 6's authorization model. Adds an RBAC tab to --unified reports with an identity privilege heatmap (users/service accounts × apps), a group privilege heatmap, and an identity × group matrix showing direct vs. inherited membership. Raw capture lands in a sidecar file and is deleted after the report generates — nothing extra sticks around on disk.

CLI

Browser setup, now encrypted end-to-end

env create now asks how you'd like to set it up — in the terminal or in your browser. The browser form collects the whole environment, credentials included, and exports it as one AES-256-GCM bundle (.atlasenv.enc) protected by a one-time passphrase shown right in the browser. env create --from-file <bundle> decrypts it, tests connections, and stores your secrets — no re-typing credentials into CLI prompts. The bundle shreds itself after a successful import (--keep-file to keep it), and you can reload one back into the wizard to fix a field and re-encrypt.

WebUI

Support Bundle viewer, redesigned

The HTML viewer now matches the Unified Report design language — Sora/Hanken Grotesk fonts, warm paper palette, card layout. New: log search with keyword filtering, date range pickers, and Error/Warn/Info level chips across every log source, so tracking down one bad night in the logs no longer means scrolling a giant flat file.

CLI

network_policy: allow / disallow

A new config edit setting (default "allow") that, set to "disallow", blocks every outbound connection to a third-party service not part of the audited environment — Google Fonts in reports (swapped for embedded fonts), GitLab adapter version checks, GitHub ruleset updates, webhook notifications. Existing installs without the field resolve to "allow" automatically, so nothing changes unless you flip it.

Also new

More in this release

Unified Report Summary redesignedCLI + WebUI

Snapshot cards are grid-based now (was nested flex), so metric text stops collapsing to one line. Each card shows an uppercase label, status dot, bolder status-colored number, and evidence rows — 4 columns / 2 rows above the fold on wide screens.

env edit / config edit use theme colorsCLI

env edit field labels and config edit section headers (Behavior, Security, Timeouts, Appearance) now render in your active theme's primary color instead of the terminal default.

Consistent CLI status glyphsCLI

Success, error, warning, and skip indicators now use one symbol set (✓ / ✗ / ⚠ / ⊘) and follow your active theme everywhere — commands, the --version banner, and setup/preflight prompts alike.

SSL verification in config editCLI

verify_ssl now lives under the Security section of config edit instead of being a config-file-only workaround — disable it for self-signed certificate environments.

Theme picker moved into config editCLI

config theme is gone as a standalone command; the same interactive picker with color swatches now lives under the Appearance section of config edit.

Redis Key CountCLI

Capture now records total Redis key count as an informational metric (no pass/fail) in the Architecture Report's Performance tab and the Unified Report's Validation Checks tab.

Reliability

Fixes & changes

Preflight failed on ~-based SSH key paths. An SSH key configured as ~/.ssh/id_ed25519 made preflight report a "No such file or directory" error because the leading ~ was passed to paramiko literally. Preflight now expands ~ before connecting, matching the capture path.
XSS in the Manual Collection Checklist guide. A user-controlled HOST value stored in localStorage was rendered unescaped through the command syntax highlighter; all non-static content is now HTML-escaped before injection.
PLAT-047 false failure on masked config values. The Platform API masks sensitive values rather than returning the real setting. Rules evaluated against a masked API response now PASS; rules evaluated against a masked alt-path value now SKIP instead of incorrectly failing.
Manual capture reported mode as "Standard" on Extended environments. The report header now shows the correct tier label regardless of capture mode.
Capture progress heading had a malformed style tag. The "CAPTURE PROGRESS" panel title used an unclosed bold tag, leaking bold styling into the rest of the panel; the tag now closes correctly.
Preflight omitted the credential-store result from Phase 0. The credential check landed outside the "Credential Store" section and wasn't shown in most cases; it now always appears under Phase 0 as intended.
