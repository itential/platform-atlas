Platform Atlas — Release Notes

What's New in 3.0

The largest release since Atlas began. Everything is renamed to Itential's current branding—Itential Platform and Itential Gateway—a new read-only MCP server allows an MCP client such as Itential FlowAI to query your audit data, the compliance score now weighs critical findings heavier, the architecture form fills itself in, and dropping Parquet and pandas makes Atlas roughly 200 MB lighter.

Headline

The big ones

Six changes that reshape how Atlas is named, how it scores, and how much it weighs—across the CLI, the WebUI, and the new MCP surface.

Plate 01CLI + WebUI

Say hello to Itential Platform & Itential Gateway

Atlas now speaks Itential's current branding end to end: Itential Automation Platform → Itential Platform (and IAP → Platform), and Itential Automation Gateway → Itential Gateway. Gateway rule numbers changed from IAG-XXX to IG-XXX—update any profile overrides or continuous-audit watchlists that reference the old IDs.

Plate 02CLI + WebUI · MCP

Ask your audit data anything—read-only

A new Atlas MCP server allows an MCP client—such as Itential FlowAI to query the sessions already in your ~/.atlas—compliance summaries, the rules that fail across the most environments, how a score is trending, what regressed, side-by-side comparisons—without re-running a capture and without being able to change anything. It ships in the WebUI (platform-atlas-webui --mcp-server) with its own port, bearer-token auth, credential redaction, and an audit log; the CLI adds the cross-environment query engine behind it, so all three surfaces answer from one codebase.

Plate 03CLI + WebUI · Extended

The architecture form fills itself in

On Extended-tier environments, env architecture and the WebUI's Run auto-detect pre-fill what they can see over read-only SSH—server specs, OS, container/VM/Kubernetes signals, SELinux, FIPS, MTU, detected monitoring/log/scanner agents, instance and replica counts, datacenter placement, and topology. Nothing you've already answered is overwritten. The report's Architecture page now draws a deployment topology diagram from those answers and real hostnames/IPs, with unanswered sections shown as dashed placeholders rather than silently assumed.

Plate 04CLI + WebUI

A compliance score that weighs what matters

The HTML report, CLI score panel, and JSON export now show a severity-weighted score—a critical failure pulls the number down five times harder than an informational one, instead of every failure counting equally. The original unweighted score is kept alongside it for comparison. Eleven rules were raised to critical (gateway TLS/certificate gaps, platform default-user, Vault, and Redis findings; a twelfth rule moved from info to warning), so they now weigh accordingly.

Plate 05CLI

≈200 MB lighter, and faster on every command

Validation results now save as 02_validation.json instead of Parquet, so sessions load faster and no longer need the old workaround that re-read the capture file to restore lost metadata. Dropping that format let us remove pandas, pyarrow, and tabulate—plus the unused pycryptodome and semver—trimming roughly 200 MB off the install (a real win for the air-gapped offline bundle) and 60–80 MB off cold-start memory on every invocation.

Plate 06CLI + WebUI

Baselines, and a ruleset you set once

Environments can now pin a validated session's results as a baseline—env baseline set/show/clear keeps a durable per-environment copy, and session diff --use-baseline checks any session against it without naming two sessions. Environments also remember their ruleset and profile: session create no longer asks every time—only once per environment, changeable anytime with env edit. In the WebUI, pin, change, or clear a baseline from an environment's page, and compare against it from the Diff page.

Also new

More in this release

horizon-contrast themeCLI

A pure-black, maximum-contrast theme verified against WCAG AAA (7:1), aimed at low-vision users and other accessibility needs. Pick it from config edit or the setup wizard.

Modern is the new default themeWebUI

A navy, brass, and sky-blue theme built from the dashboard masthead's crystal motif. The theme list is curated to four: Modern, Itential, Obsidian, and Carbon. Aurora, Horizon, Meadow, and Dracula are retired, and any setting that used one now opens on Modern.

Rulesets can require a minimum Atlas versionCLI

Atlas refuses to activate a ruleset built for a newer release instead of silently misapplying it.

session prune --legacy-filesCLI

Cleans up orphaned 02_validation.parquet files left behind by the storage change; config doctor now flags their presence and how much disk space you'd reclaim.

Per-credential format checkWebUI

Each stored secret gets a "Check format" button that confirms its shape—a URI parses, a MongoDB URI carries an authSource, a token is non-empty—entirely on this machine, without connecting out.

One shared secret editorWebUI

The Credentials page and the Extended-tier setup walkthrough now use one identical editor and a single shared Vault form, and each names the active backend honestly (OS keyring vs. encrypted file).

The dashboard, regroupedWebUI

The homepage no longer reads as a long stack of boxes—welcome banner, key stats, activity, and session/environment status are grouped into a few clean panels.

Environment Type, now requiredCLI

The old optional "Banner Tint" is renamed Environment Type and required when creating a Standard or Extended environment.

SaaS environments now use PlatformCLI + WebUI

SaaS environments connect through Platform OAuth and run a small, read-only set of adapter and application checks—no PLAT-* compliance rules and no Platform SSH. The gateway is now optional: Gateway 4, Gateway 5, both, or Platform only.

The Node.js check adapts to your Platform releaseCLI

PLAT-011 expects Node 20.x on Platform releases below 6.6 and Node 22.x on 6.6 and above, instead of always requiring Node 20.x.

Under the hood

Faster captures

Adapter Version Check runs its six workers truly in parallel—concurrent GitLab lookups overlap now, instead of funneling through one shared rate limit.

The Gateway4 API collector stopped fetching /status twice per capture—it reuses the initial connectivity check's response.

The Kubernetes collector's per-capture kubectl calls dropped from five to three—pods, HPAs, deployments, and statefulsets are fetched together.

Removing pandas and pyarrow cut cold-start memory 60–80 MB on every command, not just reporting—both were imported unconditionally.

Reliability

Fixes & changes

Support for legacy Platform 2023.x has been dropped. Itential's 2023.x support window is closing and no Atlas environments target it today, so the 2023.x ruleset, its nine profiles, and the legacy_profile / "Legacy" environment field are gone from both the CLI and the WebUI.
The Redis client library was upgraded to 8.1.0. No config or ruleset changes are needed.
Gateway4 discovery no longer misidentifies a system-wide install as a broken virtual environment. Atlas used to locate the interpreter by checking whether the service binary sat in a directory named bin—true for a venv, but also for /usr/local/bin—and then hunt for a python that was never there. It now reads the interpreter straight from the service binary's shebang line, which is correct however Gateway4 was installed.
A password-protected OS keyring no longer re-prompts for its password over and over in one command. A wrong or unavailable password on one credential used to silently force every later credential to re-prompt too, failing closed in a non-interactive context. Atlas now unlocks it once per command, with a clear retry on a wrong password.
Gateway4 Packages no longer fails with SecurityError: Command not in allowlist for a valid interpreter path. The allowlist didn't recognize python3 or properly match paths under an already-allowed directory; both are now accepted.
The MongoDB architecture question can finally represent a single-instance deployment, and HA2 stops warning about an even replica-set count—both were noise, since Atlas only ever connects to each role's primary.
A passing boolean rule no longer shows Expected: False beside Actual: false. Both render in the same lowercase form now, and PLAT-001's expected value—the one bool rule authored as a string—is a real boolean. ruleset info run with no argument also no longer crashes; it falls back to the active ruleset as documented.
SaaS environments no longer trip a schema-validation warning on JSON export. The report schema hadn't learned about the SaaS tier, so every saas export logged a spurious failure even though the file itself was fine.
The WebUI handles pre-3.0 sessions and locked keyrings gracefully. Opening a report for a session captured before 3.0 now explains it needs re-validating instead of returning a bare 404, and the Credentials page reports a password-locked keyring as locked—letting you unlock it right there—instead of showing every secret as "missing." Validate, Report, Diff, and JSON export were also updated for the new JSON validation storage.
