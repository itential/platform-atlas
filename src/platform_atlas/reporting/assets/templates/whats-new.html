What's New in 2.3

Every report and browser page Atlas generates now shares one design—off-white paper, serif headline type, a single accent color. session run report settles on one report.html for good. MongoDB and Redis can now be reached through a jumphost, and Kubernetes environments can capture multiple namespaces. Any Extended validation check can be switched off individually from config edit.

Headline

The big ones

The changes that touch every session, every environment, and every page Atlas produces.

CLI + WebUI

Every page Atlas generates now shares one design

report.html, session diff, the session export cover splash page, and all three browser wizards (env create, tier upgrade, the architecture-overview form) moved to the same warm, paper-toned look—off-white paper, serif headline type, a single accent color—in place of the previous mix of dark-dashboard and blue/pink styling. The result reads as one consistent product instead of a handful of differently-styled pages.

CLI

session run report now builds one report.html

Compliance, Operational, and Architecture ship as pages in a single file—the report that used to require the --unified flag is now the only report Atlas produces. The old three-file structure (03_report.html, 04_operational.html, 05_arch.html) and the --unified flag are gone; session export and the export splash page now point at report.html.

CLI · Extended

MongoDB and Redis, reachable through a jumphost

For Extended-tier deployments where Atlas can't connect to the database directly, a new advanced, opt-in setting—in env create/env edit, the tier upgrade walkthrough, or either browser form—tunnels those connections through a bastion host you control, with a live connectivity test before anything is saved. session run now checks the jumphost's socket alongside your other ControlMaster nodes before capture starts, offering to open it automatically if it isn't ready.

CLI + WebUI · Kubernetes

Kubernetes: multiple namespaces in one capture

An advanced, opt-in Additional namespaces option (in env create/env edit, the tier-upgrade walkthrough, or the browser setup form) covers the rare case of a second Platform or Gateway 5 deployment living in its own namespace or cluster. Each additional namespace is captured and validated independently, with its own pass/fail results shown in the report.

CLI + WebUI

Turn off individual validation checks

config edit has a new Advanced section listing every extended validation check with a checkbox, so any check that's too slow, invasive, or not relevant to your environment can be disabled without touching rulesets. A disabled check shows as "Module Deactivated" in the report rather than looking like a failure. The standalone role-based access control (RBAC) authorization setting is gone—it's now just one more module in this list (still off by default).

CLI

preflight, now one tree

The stacked per-phase tables and interim "Phase N…" lines are replaced by one grouped tree—a branch per phase, with per-branch pass/warn/skip/fail tallies—and a single progress spinner that updates as checks run. Failures and warnings show their fix detail inline, so a scan of the tree tells you everything.

Also new

More in this release

Basic TLS for MongoDB/RedisCLI

env create/env edit now offer an independent "Enable TLS" setting for each database, so a deployment can require Transport Layer Security (TLS) on one and not the other. Encrypts the connection but doesn't verify the server's certificate—these audits overwhelmingly target self-signed certs.

Organization name, set onceCLI + WebUI

Collected once during initial setup and used everywhere; environment setup, env edit, session edit, and the architecture form no longer ask again. Change it later from the new Organization name option in config edit.

config doctor reports ~/.atlas sizeCLI + WebUI

A new Runtime line shows the total on-disk footprint of your Atlas data directory—sessions, captures, reports—also shown on the WebUI Config Doctor page.

Wider screens get a backdrop panelCLI + WebUI

The environment setup, tier-upgrade, and architecture-overview forms fill the empty space beside a centered form with a soft animated backdrop and a short note about what the page does.

New rule: audit logging enabledRuleset 1.0.6

PLAT-050 flags Production systems that aren't tracking detailed audit events—one more platform-category check.

iagctl found even when it's off PATHCLI

Checks now look in /opt/gateway/iagctl and /usr/local/bin/iagctl directly, and retry with sudo when permissions block direct access, instead of requiring the binary on the SSH user's PATH.

Rule details flag assumed defaultsCLI + WebUI

When a setting isn't configured, the report now says so explicitly and explains that Atlas evaluated it against Gateway 5's documented default instead.

Reliability

Fixes & changes

HA2 captures could report the wrong node's system data. When multiple nodes shared a role (e.g. a 3-member MongoDB replica set), whichever node happened to be captured last silently overwrote the others' system/log data, and it wasn't reliably the primary node. Every node's data is now correctly attributed instead of randomly overwritten.
Redis Access Control List (ACL) showed "No data" even with a working Redis connection. The check only ever read ACL rules by parsing redis.conf over SSH, and that SSH read was skipped whenever the separate CONFIG GET call succeeded—so a direct Redis connection with no SSH access always came up empty. Atlas now reads ACL rules from Redis directly first, falling back to redis.conf over SSH only if that fails.
Kubernetes settings couldn't be edited without re-running the topology wizard. env edit → Deployment Topology now offers an "Edit Kubernetes settings" option to change the namespace, kubectl context, values.yaml paths, and kubectl binary directly, instead of requiring the entire topology to be replaced.
16 Gateway 5 rules failed or skipped instead of passing when a setting was left at its default, including the venv pruner interval/retention checks. They now correctly evaluate against Itential's documented defaults.
The Gateway Connect Insecure TLS rule (IAG-016) had inverted pass/fail logic and now correctly passes when insecure TLS is disabled.
session diff could compare sessions from different environments, producing a misleading change report. It now scopes the picker to the active environment and blocks the comparison outright if two explicitly named sessions don't match.
