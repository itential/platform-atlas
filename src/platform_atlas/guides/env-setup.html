Audit Tier
Select the audit scope for this environment. You can change it later with platform-atlas tier set.
Standard
Application audit via Platform OAuth. No SSH or infrastructure access required.
  • ~56 rules across platform & gateway4 categories
  • Platform OAuth credentials only
  • Optional IAG4 API token
  • No SSH, MongoDB, or Redis access
Extended
Full infrastructure audit. Requires SSH to IAP, Mongo, and Redis servers.
  • ~122 rules across all categories
  • SSH + pymongo + redis-py collectors
  • System, filesystem, and gateway collectors
  • Kubernetes support
SaaS
Single-gateway audit. GW4 or GW5 only. No Platform, Mongo, or Redis.
  • Gateway-only rule categories
  • GW4 (API) or GW5 (SSH/file) source
  • Generates single merged compliance report
  • Tier is fixed at environment creation

Credential Storage
Choose where Platform Atlas will store secrets (API keys, passwords) for this environment. Credentials are never written to the JSON file — this just tells Atlas where to look at runtime.
OS Keyring Recommended
Stored in the system credential manager (Keychain on macOS, GNOME Keyring on Linux, Windows Credential Store). Most secure option when available.
Encrypted File
Stored in ~/.atlas/credentials.enc with AES-256-GCM encryption. Use if your OS keyring is unavailable (headless servers, containers).
HashiCorp Vault
Stored in Vault KV v2. Advanced use — requires separate Vault configuration with platform-atlas config vault.

Next steps:
1. Generate the bundle and save the one-time passphrase it shows you (a password manager is ideal)
2. Run: platform-atlas env create --from-file ~/Downloads/atlas-env-<name>.atlasenv.enc
3. Enter the passphrase when prompted — Atlas decrypts, verifies connections, stores your credentials, then shreds the file
4. Made a mistake? Re-open this page, click Load existing bundle, fix the field, and generate again
5. Run platform-atlas session run all to start your first audit
